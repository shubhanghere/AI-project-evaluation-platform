# Security design

Treat archives, repository URLs, source files, README content, dependency manifests, and model output as hostile. Keep public API, orchestration, and untrusted parsing/execution boundaries separate. Never execute submitted code in API or privileged worker processes. Parser workers should run as non-root with read-only base image, ephemeral quota-limited storage, CPU/memory/PID/time limits, no credentials, and default-deny network egress. If running tests is later offered, use disposable microVM/container sandboxing with syscall policy and independent control plane; residual kernel escape risk remains.

Uploads use short-lived signed URLs for one random object key, strict size limits, checksums, content sniffing, malware scanning/quarantine, archive path traversal/symlink/bomb limits, and encryption. Block executable files where unnecessary. URL fetchers must resolve and reject loopback, private, link-local, multicast, and cloud metadata ranges at every redirect; pin/validate DNS resolution at connect time to mitigate rebinding, and enforce network egress allowlists outside application checks. Avoid fetching arbitrary URLs where direct user upload or provider OAuth is possible.

Production uses OIDC, tenant/course-scoped RBAC, least-privilege IAM task roles, TLS, KMS-backed encryption, secret manager, audit events, request quotas, and retention/deletion workflows. Use parameterized SQL and output encoding for rendered feedback. Add CSRF protection when cookie auth is used. LLM prompt injection is handled by treating project text solely as quoted evidence, separating instructions from data, tool-free model calls, structured output validation, and deterministic policy checks; this reduces risk but cannot make model output trusted. Send only minimized data to contracted providers and document provider retention/training settings per current contract. PoC implements no auth and must stay local.
