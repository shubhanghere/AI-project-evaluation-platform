# Evaluation pipeline

Create an immutable project manifest; classify source, tests, docs, configuration, generated/vendor files, and binaries. Exclude secrets and oversized/noisy files. Parse in isolated workers; normalize and chunk by language/symbol with path, line range, content hash, and file role. Use lexical search first; add embeddings and pgvector when measured retrieval needs justify them. Retrieve evidence per criterion under token budgets; do not put an entire repository into one prompt. Use staged analysis: project map, criterion-specific evidence, structured criterion judgments, then consistency checks. Keep model output as untrusted proposal: validate schema, allowed score range, evidence references, coverage, rubric/prompt/model version, and confidence; deterministic service computes weighted score `sum(score_i * weight_i / 100)`.

Provider adapter exposes evaluate and health/capabilities; deterministic mock is offline-only. Production records provider/model, prompt template hash, token usage, latency, cost, retries, and evidence provenance. Route low confidence, contradictions, missing evidence, unusual score distribution, and policy cases to human review. Calibrate with a labeled benchmark set, inter-rater review, drift checks, fairness checks, and prompt/model version gates before rollout. LLM judge is decision support, never proof of correctness.
