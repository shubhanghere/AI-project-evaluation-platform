# Reliability and recovery

Production uses a transactional outbox: commit submission/job/outbox together, relay publishes at least once, then marks published. Worker processing is idempotent by job ID and attempt; persist each stage boundary and immutable artifacts. Lease row/heartbeat and SQS visibility extension must exceed heartbeat interval; acknowledge only after durable result commit. Redelivery is expected. Transient timeouts, throttles, and 5xx use capped exponential backoff with jitter; invalid inputs, policy violations, and schema failures are terminal or reviewable. Bound attempts, then DLQ with alarm and replay tooling. Reaper detects expired leases and requeues safely. Cancellation is cooperative between stages.

States: CREATED → UPLOADING → QUEUED → PROCESSING → EVALUATING → COMPLETED; EVALUATING → REVIEW_REQUIRED → COMPLETED; retry path PROCESSING/EVALUATING → RETRY_WAIT → QUEUED; terminal FAILED and CANCELLED. Enforce transitions with compare-and-set/version checks and append-only events. Metrics include queue age/depth, stage durations, retry/DLQ counts, lease expiry, provider latency/rate limits, tokens/cost, parse rejection, human-review rate, and result quality. PoC has a volatile polling worker: process crash can leave PROCESSING stranded and there is no durable retry broker; restart reconciliation and SQS are production requirements.
